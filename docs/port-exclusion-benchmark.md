# 端口排除准备阶段基准测试

将 Tokio master 分支 `b7119f7f3eb1601e81126ef3572699ed7b3b7c0b` 与实现
`270561d553688acbd99f61c460cdfa7c76c1423e` 在 2026-10-02 进行了对比。

## 方法

启用了 LTO 的 release 构建，Rust 1.98.1，Intel Core Ultra 7 165U，
Linux 7.2.6-1-cachyos。两个版本使用相同的 lockfile 和完全一致的
`benches/benchmark_helpers.rs`；在构建基准工作树之前，先把最终的基准框架
复制到该工作树中。基准测试运行生产环境的
`Scanner::run_with_status`，**目标地址数量为零**，因此它不打开任何
套接字，也不做 DNS 或脚本操作。它包括生成/克隆端口列表、过滤和空扫描
准备。Scanner 的构造以及当前线程 Tokio 运行时的构造都在计时器之外。

手动端口为 `1..=port_count`；排除项为对 `0..excluded_count` 中的 `i`
计算 `(i * 13 % 65536) as u16`。每个用例对每次构建都有两个独立的、
二十样本的 Criterion 运行、500 ms 预热和 2 s 目标测量。用例在 CPU 0 上
按 A/B 然后 B/A 的顺序运行。计时期间没有构建或其他本地检查运行。
这台共享笔记本电脑上没有锁定 CPU 频率，因此表格保留了两次重复，
而不是只挑选一个结果。数值为 Criterion 的均值点估计。

每个工作树的构建命令：

```sh
cargo bench --locked --bench benchmark_helpers --no-run
```

随后按顺序运行保存下来的基准可执行文件，对每个用例：

```sh
CARGO_TARGET_DIR=/tmp/preparation-results taskset -c 0 /path/to/benchmark_helpers \
  --bench 'port preparation/65535 ports, 4096 exclusions' --save-baseline base-a
```

接着用候选二进制作为 `head-a` 重复，然后用候选作为
`head-b`、基准作为 `base-b` 重复。要在不比较构建的情况下正常运行该组：

```sh
cargo bench --locked --bench benchmark_helpers -- 'port preparation'
```

## 实现与正确性

当没有排除项时，保留已经生成的 vector。对于少于 64
个端口的情况，用线性成员检查就地过滤；这避免了位图
设置和第二次分配。更大的列表使用一个 8 KiB 位图，覆盖
`u16` 可表示的全部 65,536 个值，然后就地保留端口。这
把大列表的过滤成本从 端口数 × 排除数 变为 端口数 +
排除数，同时保留顺序、重复端口和边界值。这个辅助函数
保持为不内联的：release 汇编显示，被内联的位图在每个 async poll 中预留
8,424 字节，而最终的 poll 帧只使用
344 字节，辅助函数仅在准备阶段预留它的位图。

探索发现，就地的线性成员检查会拖慢大用例。第一个生产环境
候选实现也拖慢了 64 端口配 4,096 排除项的情况；对该
情况改用位图，在最终匹配运行之前纠正了这一回归。这个阈值是一个性能
选择，而不是对输入的限制。

一个专门的无网络回归测试将实现与一个独立的成员判定
oracle 进行对比，覆盖空输入、端点 0/65535、重复端口/排除项、
全部端口，以及一个冻结的随机顺序。
`cargo test --locked` 通过 74 个测试，其中有一个先前存在的被忽略的 doctest。
全目标的 Clippy、格式化、文档和 diff 检查都通过。仅 CI 使用的扫描框架
用一个排除端口扫描增加了使用现有监听器的检查，
验证预期结果，并使用实际尝试的套接字数量来计算吞吐量。

[原始 Criterion 样本、置信区间、修订版本和二进制哈希](port-exclusion-benchmark-results.json)
已附上。托管环境下的正确性/性能结果在 PR 中链接。

## macOS 运行器配置

在 Darwin 25.6 上重复的托管扫描在 master 和候选实现上都返回了 `ENOBUFS`
（错误 55），缺失 fixture 监听器。这类运行对性能声明而言是无效的。
该工作流在测量任一构建之前一次性配置 TCP 内存
预算，必要时将其从默认的物理内存 1/32 提升到 1/8，并打印实际的限额
和分配计数器。它保留每个场景、重复、监听器
对比和性能阈值。一次立即进行的、不计时的诊断
扫描会在某个被测量的配对错过监听器时记录错误和内核计数器；
该失败的数据集不会被用来声称加速。

这使用了 XNU 的 [TCP 预算初始化](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/netinet/tcp_subr.c)
和 [内存记账接口](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/mem_acct_private.h)。
它改变的是可丢弃的基准测试环境，而不是 RustScan 的行为
或用户机器上的操作系统配置。
