# 惰性 DNS 初始化基准测试

将当前的 Tokio master 分支 `67c08a33100362c54b56fde784b0fd234f70fa11` 与位于
`a05592a8a88b77ad85d961137943dfadfe98b612` 的惰性解析器实现在 2026-10-02 进行了对比。

## 方法

两个二进制文件都是启用了 LTO 的 release 构建，使用 Rust 1.98.1，
运行在配备 Intel Core Ultra 7 165U、Linux 7.2.6-1-cachyos 的机器上。每个工作负载
对每个二进制使用二十次测量运行和两次预热，交替 A/B 与 B/A 顺序。二进制
使用 CPU 0-3；测试框架使用 CPU 8-9。测量期间没有进行任何构建。

测试框架在一个私有网络命名空间中运行。每次调用都排除了它唯一请求的端口，
因此不会发送任何扫描流量。配置和脚本均被禁用。计时范围从进程启动一直到退出，
两个构建都使用相同的 `taskset` 亲和性启动器。

公共参数：

```sh
--no-config --config-path /dev/null --no-banner --scripts none --greppable \
  --ports 80 --exclude-ports 80
```

字面量 IP 场景额外加上 `-a 127.0.0.1`。混合场景额外加上
`-a 127.0.0.1,192.0.2.0/30,2001:db8::/126` 和
`--exclude-addresses 192.0.2.1,2001:db8::1`。两者都使用 `RUST_LOG=rustscanx=info`。

## 结果

| 工作负载 | Master 中位数 | 惰性 DNS 中位数 | 节省时间 |
| --- | ---: | ---: | ---: |
| 字面量 IPv4 | 168.23 ms | 2.25 ms | 165.98 ms (98.66%) |
| IPv4/IPv6 CIDR 与排除项 | 178.09 ms | 2.45 ms | 175.63 ms (98.62%) |

全部 88 次调用都成功退出，并产生预期的空扫描输出。
对优化后的字面量 IP 调用单独进行的系统调用跟踪记录显示，没有
读取 `/etc/hosts` 或 `/etc/resolv.conf`，也没有任何网络连接或发送。

这台主机有一个 2,760,051 字节的 hosts 文件。即使目标是纯数字地址，
主动式 Hickory 初始化也会解析该文件。hosts 文件更小的系统节省会更少；
这里衡量的是 CLI 启动，而不是套接字吞吐量。需要回退 DNS 的主机名
仍然会支付一次解析器初始化开销，而解析顺序、文件处理、去重
和排除项都保持其现有行为。

[原始样本、环境与二进制哈希](lazy-dns-benchmark-results.json)已附上。
无网络的回归测试验证了字面量 IPv4/IPv6 目标、
CIDR、排除项、重复项和空输入都不会构造解析器。
